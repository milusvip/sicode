为什么这三处一定要改

问题现状代价共同修法
一个字号撑全部层级 项目名、会话标题、时间全在 12px，只靠 font-weight: 500 分层。DESIGN.md 已写明「400 对 700 才扛得住雅黑，460 对 400 看起来一样重」——所以现在的层级其实没生效。 会话标题升到 13px/16px（正文级），项目名留 12px 当标签，时间 11px 当元数据。三级落差靠字号 + 字重，不靠颜色深浅硬凑。
时间戳永远占位 224px 里缩进 42px、右侧时间 40px，标题只剩 ~105px，中文 8 个字就开始省略。「自动恢复停止排查」在截图里已经被截。 时间 / 运行中 / ⋯ 共用一个 44px 固定槽，三者互斥永不同时出现。右边缘对齐成一列（数字列右对齐是 DESIGN.md 的硬要求），宽度不再随内容抖动。
组内 0px、组间 14px 行与行贴死、组与组拉开，读起来是一块块板砖，而不是一棵树。 组内 1–2px、组间 14px、组头到首行 4px。层次靠距离，不靠分割线（现在头部那根 1px 线也可以去掉）。
选中态靠竖条猜 浅色主题下 overlay-pressed 只是 8% 黑，和 hover 的 4% 几乎分不开，实际靠 2px 竖条认位置。 选中 = layer-02 实底 + 文字升到 text-base + 2px 竖条，三重信号；hover 只给 6% overlay。深浅主题都不含糊。

三个方向的取舍

方向改了什么代价 / 适合
A · 静默导轨 结构原样：项目分组 → 会话。只修工艺，宽度 224 → 256。 改动最小、风险最低，今天就能落。项目多时仍要滚很久才能跨项目找会话。
B · 时间线 按「今天 / 昨天 / 更早」分组，项目退成行首 2px 色标；顶部换成项目切换器 + 新建；底部是「所有项目」+ 设置。 和首页的历史列表同一套分组语义，跨项目找「刚做的事」最快。代价是失去「按项目纵览」的视角，需要项目切换器补回来。
C · 双行 标题一行不截，第二行放「项目色标 · 时间 · 状态」，行高 42px。 长中文标题最友好，也不用加宽侧栏。代价是同屏少三行、垂直滚动变多。

我的建议：B 的骨架 + A 的工艺。 理由是侧栏真正的用途是「回到刚才那个会话」，而现在为了按目录纵览，付出了 42px 缩进 + 常驻项目头两层开销。 如果把项目降级成 2px 色标、按时间分组，标题立刻多出 ~50px，同时还能顺手解决「项目多到要滚」的问题—— 项目切换器只需要承载「换目录开工」这一件低频事。
想更保守就先落 A：它是 B 的真子集，之后换分组方式不用再动排版。

落点：packages/app/src/shell/left-sidebar.tsx（结构与 class）、packages/app/src/runtime/i18n/en.ts（B 需要 dock.group.today/yesterday/earlier、dock.projects.all）。
不动：会话排序、归档、右键菜单与跳转目标。新增：行内 ⋯ 复用现成的 sessionMenu。
