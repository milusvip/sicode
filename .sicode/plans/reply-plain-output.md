# 让最终回复说人话（方案复核）

> 用户追问「你确定是最好的方案吗」。这份是第一版的自我复核，不是新需求。
> 复核结论：闸门仍是首选，但第一版写得太粗——触发信号要重画，重写文案要具体，否则会变成一个白花一次生成的摆设。

## 目标

最终回答的**正文**是可读的白话：说的是「发现了什么 / 改了什么 / 还差哪一步」，而不是一串路径、字段名、JSON 片段、解码过程。用户明确抱怨的是这个，不是排版、不是渲染。

## 非目标

- 不动 CSS / 渲染层（`markdown.css`、`message-content.tsx`）。已确认与「正文是代码不是白话」无关。
- 不禁止正当技术细节：用户问「这个函数怎么改」、要 diff 时，回答里出现函数名、代码块是对的。
- 不重写 `system.txt` 的 Communication 整段。

## 为什么之前的修法不管用（证据）

- 规则存在且被绕过。`runner/prompt/system.txt:13-14` 明禁 `path → symbol → detail` 清单，第 17 行明禁「正文提问然后停」。截图那条两条都踩了。
- 仓库自身结论：Flash 扛不住长 system 纪律，元规则约 4~5 条饱和（`.sicode/plans/cursor-parity-search.md` §2.1）。`plugin/system-prompt/deepseek.txt` 是 `append`，还整段重复 RE / Authorization，把文风规则稀释掉。
- 但仓库里**被触发的过程性提示词是有效的**：completion-gate、search-miss、browser-drive-gate 都是「静态规则被无视 → 改成触发式提示后生效」。这是支持闸门的直接先例。

## 方案对比（诚实排序）

| 方案 | 杠杆 | 成本 | 判断 |
| --- | --- | --- | --- |
| A 只精简提示词 | 静态规则 | 0 | **否决**。就是之前失败的那一类；`deepseek.txt` 删重复段可做，但不足以解决 |
| B 新增回复闸门（触发式重写） | 触发式 | 超标回合多一次生成（按 notes 换算率 ≈5–8s） | **推荐**，与仓库既有闸门同构 |
| C 并进 final-answer-gate | 触发式 | 同上 | **否决**。那个闸门的契约是「你一个字都没说」，机械信号干净；塞进「说得难读」会污染它。仓库风格是一闸门一信号，新文件反而一致 |
| D UI 重做（Cursor 式：文件引用变可点 chip、字段倾倒折叠） | 根因 | 大，收益不确定 | 缓。它解决「不必写路径」，不解决「把解码过程当答案」 |
| E 渲染层隐藏行内代码 | — | — | **否决**。只是遮掉，不改产出 |

**为什么不是 C（就地扩展）**：仓库里 completion-gate / continue-intent-gate / browser-drive-gate / final-answer-gate 各占一个文件，一个信号一个契约。把「文本形态」塞进 final-answer 会让那个「沉默回合」信号不再可读。

## 推荐方案（B，重画后的版本）

新增 `packages/core/src/session/runner/reply-style-gate.ts`，形状照抄 `continue-intent-gate.ts`（导出 `指纹函数 + PROMPT 常量`），接在 `llm.ts` 第 778 行 final-answer-gate 之后，带 `// SiCode:` 注释。

### 触发信号（第一版太粗，这是重画的关键）

只在**用户要的是解释而不是代码**、且回复**结构上不像人话**时触发：

1. **先剥围栏代码块**。用户要 diff / 要贴代码 → 回复主体是 fenced block → 直接豁免。这是最干净的误报挡板。
2. 在剩余的散文里数：
   - 完整句子数（以 `。！？.!?` 收尾的句子），**少于 2 句**；且
   - 行内代码片段 / 汉字数 的比值超标；或
   - 连续 ≥3 个加粗/`#` 小标题行。
3. 三个里「句子太少」是主判据，其余是加固。这样「技术对话但用完整句子讲清」不会误伤。

### 重写文案（要具体，不能只说「用白话重写」）

第一版只说「重写成人话」太软。文案改成可执行约束：

> 你刚把调查过程当答案交上来了。用 2–4 句完整的话回答用户：发现了什么、改了什么、还差哪一步。
> 不要把路径、字段名、JSON、试过的关键词列进正文；用户要开某个文件时，在句子里提它的名字就够。
> 不要加小标题、不要用列表，除非用户明确要的是清单或代码。

### 去重

指纹 = 用户那轮的 `message.id` + 文本摘要，`Set<string>` 一次触发；与 `answerNudged` 同款。

## 风险（如实登记）

1. **重写可能是白花的**：模型被推一下未必换风格，可能只少写两个路径。这是本方案最大不确定性。缓解：文案足够具体 + 只在强触发时用。
2. **误报**：用户要代码/清单时不该触发。缓解：先剥围栏块（见上）。
3. **成本**：超标回合多一次生成，约 5–8s。只在超标时付。
4. **上游文件**：`llm.ts` 是上游文件，接线必须带 `// SiCode:`（见 `UPSTREAM.md`、`.sicode/rules/upstream-edits.md`）。
5. **阈值是猜的**：没有真实回放数据，初版阈值必然偏保守或偏松，需要录一段真实会话再定。
