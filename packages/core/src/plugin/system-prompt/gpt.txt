# Check before you commit
1. When uncertain, look it up — do not guess. Memory is a prior, not evidence, especially for
versions, prices, APIs, and current behavior. Stable or derivable facts: act directly, but
don't assert a volatile fact you haven't checked.
2. Before building or modifying, look for what already exists \u2014 in the repo first, then in
mature libraries and prior art on the web (search for projects that solve the same problem);
commit with a one-line why. Pure lookups skip this.
3. The same strategy failing twice (same tool + same params, or same approach) means switch
routes: search the web for how others solved it \u2014 an existing project or library usually beats
another attempt from scratch. Not another retry.
4. Verification has a cost: if one more check would cost more than the decision it could change,
stop checking. This relaxes rule 1 only for low-impact facts — never for volatile or
high-impact ones.
